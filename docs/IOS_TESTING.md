# Test AtmosIQ on an iPhone from Windows

Start with Expo Go when you have an iPhone and no paid Apple Developer
membership. The project uses Expo SDK 57, already declares the iOS bundle
identifier `com.atmosiq.weatheranalytics`, and shares its native SQLite adapter
between Android and iOS.

## Run on your iPhone

1. Install the current [Expo Go](https://expo.dev/go) app on the iPhone.
2. Create a free Expo account if needed, and sign into Expo Go.
3. Connect the iPhone and Windows computer to the same Wi-Fi network.
4. Open PowerShell on the computer and run:

   ```powershell
   cd C:\mad-project
   npx expo login
   npm run ios:go
   ```

   Use the same Expo account in the CLI and Expo Go. Current Expo Go on physical
   iOS devices requires the accounts to match.

5. Scan the terminal's QR code with the iPhone Camera and open the link in
   Expo Go. Allow local-network access if prompted.
6. Keep the development server running while testing and editing the app.

`npm run ios:go` runs `expo start --go`. The separate `npm run ios` script
opens an iOS Simulator and is intended for a Mac with Xcode.

## Check the iOS behavior

- Search for a city and load weather, forecast, and analytics.
- Check chart gestures, scrolling, keyboard behavior, and bottom-tab spacing
  around the iPhone's safe areas.
- Open **More > Local SQLite Database** and confirm that weather records are
  present. Reload the project and check local persistence.
- Open **More > XML Data Explorer** and test a refresh.
- Check Cloud Sync if Firebase client configuration is present in `.env`.
  Without that configuration, Local-Only mode is expected.

## Connection problems

- Check that both devices are on the same Wi-Fi and that the development
  server is still running.
- Confirm that Expo CLI and Expo Go use the same Expo account.
- Allow Node.js on the private network if Windows Firewall prompts you.
- An SDK mismatch message means the installed Expo Go runtime and the project's
  Expo SDK need to be matched before testing.
- If local Wi-Fi blocks device-to-computer access, Expo CLI also supports
  `npx expo start --go --tunnel`; this requires its ngrok tooling and internet
  access on both devices.

## Standalone iOS installation later

Expo Go is the development host for this test. A standalone iPhone build is an
Apple-signed iOS app, distributed separately from the Android APK.

For an installable device build or TestFlight through Expo Build, prepare an
Apple Developer Program membership and an Expo account. EAS CLI can build iOS
in the cloud from Windows. A future setup can use:

```powershell
npx eas-cli@latest login
npx eas-cli@latest build:configure --platform ios
```

Select an internal-distribution profile for registered test devices, or a
production profile for TestFlight/App Store distribution, then run the matching
`npx eas-cli@latest build --platform ios --profile <profile-name>` command.
Complete Apple signing prompts in your own terminal.

If you later have access to a Mac, Xcode also supports testing on a personal
iPhone with a free Apple account through a Personal Team. Those provisioning
profiles expire after seven days and require rebuilding/reinstalling. See
[Apple's account overview](https://developer.apple.com/help/account/basics/about-your-developer-account).

An `ios/` directory is generated by Expo when needed for a native build. Keep
native configuration in `app.json` and config plugins.

## Local JavaScript verification

```powershell
npx expo export --platform ios --output-dir .expo/ios-export --max-workers 2
npx expo lint
npx tsc --noEmit
```

An iOS export verifies JavaScript and asset bundling. Native compilation and
real iPhone behavior still need their respective device/build tests.

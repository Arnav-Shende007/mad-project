# Android APK build

The `android/` project is generated by Expo SDK 57 and can be opened directly
in Android Studio using **File > Open > C:\mad-project\android**. Wait for
Gradle sync, then use **Build > Generate Bundle(s) / APK(s) > Generate APK(s)**.

## Windows terminal

Install dependencies with `npm ci` if needed. JDK 17 and the Android SDK must be
installed, with `JAVA_HOME` and `ANDROID_HOME` pointing to their installation
directories. The first build downloads Gradle and Android dependencies, so it
requires internet access.

In Android Studio, select JDK 17 under **Settings > Build, Execution, Deployment
> Build Tools > Gradle > Gradle JDK** if Gradle cannot find the required Java
toolchain. A newer bundled JDK alone may still require JDK 17 to compile React
Native's Gradle plugin.

This workspace also has a local JDK 17 and Gradle cache under the ignored
`android/.gradle-cache/` directory. To reuse them in PowerShell, run these from
the project root before building:

```powershell
$env:GRADLE_USER_HOME = Join-Path $PWD 'android\.gradle-cache'
$env:JAVA_HOME = Join-Path $env:GRADLE_USER_HOME 'toolchains\jdk-17.0.21+9'
```

For Android Studio on this machine, the downloaded Gradle JDK is
`C:\mad-project\android\.gradle-cache\toolchains\jdk-17.0.21+9`.
These cached tools are local only; other checkouts must install JDK 17.

From the project root in PowerShell:

```powershell
cd android
.\gradlew.bat :app:assembleDebug
```

Debug APK: `android/app/build/outputs/apk/debug/app-debug.apk`.
This development APK loads JavaScript from Metro; run `npx expo start` from
the project root and connect your device to the development server.

For an APK with JavaScript and assets bundled, which can run without Metro:

```powershell
cd android
$env:NODE_ENV = 'production'
.\gradlew.bat :app:assembleRelease
```

Standalone APK: `android/app/build/outputs/apk/release/app-release.apk`.
The generated project's release variant currently uses the bundled debug
keystore, so this APK is for testing and direct installation. Configure your
own release signing credentials before publishing to Google Play.

On a machine with limited RAM (such as 8 GB), use the supplied Gradle init
script to limit native compiler concurrency as well as Gradle workers:

```powershell
# Run inside android/, after setting JAVA_HOME and NODE_ENV as above.
.\gradlew.bat :app:assembleRelease --max-workers=1 --no-parallel --init-script ../scripts/android-low-memory.gradle '-Dorg.gradle.jvmargs=-Xmx1536m -XX:MaxMetaspaceSize=512m' '-Pkotlin.compiler.execution.strategy=in-process'
```

This changes build concurrency only and produces the same standalone APK.

For a faster APK targeting current ARM64 Android phones, add
`'-PreactNativeArchitectures=arm64-v8a'` to the Gradle command. This APK does
not support ARM32 or x86 devices/emulators. Omit the option for a universal APK.

The universal APK includes `armeabi-v7a`, `arm64-v8a`, `x86`, and `x86_64`.
To request all four explicitly, add
`'-PreactNativeArchitectures=armeabi-v7a,arm64-v8a,x86,x86_64'` to the Gradle
command. This app requires Android 7.0 (API 24) or newer.

## Regenerating the native project

Keep native configuration in `app.json` and Expo config plugins. After changing
native configuration or dependencies, regenerate from the project root:

```powershell
npm run android:prebuild
```

Do not hand-edit generated Android files. The Android project is included in
version control so it is available when opening this checkout in Android Studio;
local SDK paths, build outputs, and Gradle caches remain ignored.
